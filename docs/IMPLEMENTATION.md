# Beast Dojo Implementation Handoff

The v0.242 Studio checkpoint is the starting point for new work. This repository contains the editable native implementation, an offline browser concept, the full [game design](GAME_DESIGN.md), and the [16-phase release roadmap](ROADMAP.md). The roadmap's release gates are wider than the current Studio build.

## Start here

1. Rebuild and open the Studio place using the [root README](../README.md). Use the ZIP when you want the pinned checkpoint immediately.
2. Start **Play** in one Studio window. Find the Fighting Ring, run the Lantern Relay, and visit Trophy Hall. Open the City Map to see the six districts and 15 mapped links.
3. Walk to Skywalk Peaks, climb the Wind Court ramp or stairs, and activate **Reed**, **Cloud**, then **Summit**. Try the browser concept separately to review the planned progression loop.
4. Check the appropriate phase before deciding which functionality a task should change. Record evidence for the exact build you tested.

## Shared city and personal trophy rooms

All six districts belong to one walkable Roblox city place. Players in the same server see each other and share the city and its events. Roblox can run multiple copies of the city at once. The district roads keep a group together in the same server. Roblox's Join Experience action can bring a player into a friend's session when account settings, experience access, and server capacity allow it. [Roblox friend joining](https://en.help.roblox.com/hc/en-us/articles/203314220-How-to-follow-or-join-another-player-in-experiences)

The planned **Play Together** flow adds in-game invites and regrouping. If a city server is full, offer the group a common server with enough room. Queued matches and larger raids can use separate servers and return the party to a safe city checkpoint. Test these flows in published staging with separate accounts.

The public Trophy Hall is a city landmark and the planned entrance to each player's **personal trophy room**. Each owner chooses six featured trophies plus paged wall displays. Layouts and earned trophies are saved per account and follow the owner across servers. The room defaults to private. Owners can invite guests to inspect displays, and only the owner can change the layout. The Studio build has the Hall, an owner-specific journal and the first Lantern Keeper display. Private rooms, visit invites and published multiplayer verification are planned.

### Studio MCP for coding agents

For an MCP-capable client, open one local place in Studio and enable **Studio as MCP server** under **Assistant → Manage MCP Servers**. Use Studio’s quick connect or register its stdio server in your client. The verified macOS command is `/Applications/RobloxStudio.app/Contents/MacOS/StudioMCP`. Run `list_roblox_studios` first and match the returned filename before starting Play. The CLI build and manual Studio playtest also work independently of MCP. [Roblox Studio MCP setup](https://create.roblox.com/docs/studio/mcp)

## Keep the handoff current

Edit `design/world-content.json` and rebuild the browser runtime if the prototype data changes. The owner workspace can refresh the portable GDD and roadmap using `python3 -B tools/export_owner_handoff.py` after regenerating the private plan. Its optional `--refresh-browser-data` flag deliberately copies the owner plan's district descriptions and roster into the browser prototype. Review the diff before choosing it.

After each verified implementation package, update this guide and the roadmap where relevant, run the checks, stage the related changes, and commit and push to `origin/main`. Keep deployment metadata and the owner-private notebook out of that commit.
